# Декомпозиция Levara: задачи, DoD и corner cases

Дата: 2026-10-05. Основание: функциональный анализ D1–D15 и текущие исходники.
Это backlog приёмки и исправлений, а не заявление о выполнении существующих функций.
32 задачи распределены по V0–V9. Реализация начинается с T04:
[scope-memory-pins-by-collection](../../openspec/changes/scope-memory-pins-by-collection/proposal.md).
Остальные задачи открываются отдельными небольшими changes после выполнения зависимостей.

## Общий Definition of Done

- Наблюдаемое поведение описано входом, результатом, ошибками и границами доступа.
- Подозреваемый дефект имеет воспроизводимый failing regression до production fix; уже корректное поведение подтверждается проверкой без переписывания.
- Проверены успех, отсутствие данных, запрещённый доступ и релевантные failure/concurrency/recovery пути.
- SQL-пути проходят одинаковые сценарии на SQLite и изолированном PostgreSQL; SKIP не считается PostgreSQL PASS.
- Публичные изменения включают descriptor/schema/dispatch/profile/error-shape checks и `make contract-check`; generated files меняет только генератор.
- Есть результаты команд, ревизия проверенного кода, ограничения покрытия и независимое ревью для изменений доступа/публичных контрактов/транзакций.
- Документация обновлена вместе с соответствующей функцией. Наличие теста, benchmark или флага не закрывает сквозную приёмку.
- Текущие unrelated изменения сохраняются. Deploy, live migration, внешняя публикация и изменение production data не входят в этот backlog автоматически.

| Код | Preflight |

| P | G + отдельная PostgreSQL test DB, `LEVARA_TEST_POSTGRES_DSN`, проверенная связь и право создавать/удалять test schemas; production DSN запрещён |
| M | P + явно выбранные локальные embedding/LLM/rerank endpoints и зафиксированные model/dimension/version; внешние платные providers отдельно авторизуются |
| W | Node/npm из WebUI runtime; lockfile; Playwright Chromium; локальный test API для integration-проверок |
| N | Две независимые локальные test-ноды, разные SQL/object/workspace roots; изолированные ports/credentials |
| E | Отдельный sandbox AD/IdP/S3/KMS/SIEM, согласованные test identities/resources; фактический external acceptance, локальные mocks его не заменяют |

Перед любой командой с `-run` проверить, что ожидаемые тесты присутствуют в `go test -list`; PASS с нулём тестов не является evidence.
Для нового corner case сначала добавить минимальный runnable test в существующий пакет.
