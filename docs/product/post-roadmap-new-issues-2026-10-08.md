# Новые проблемы после roadmap T01–T32

Этот файл содержит только дефекты и неясные контракты, найденные во время
закрытия ранжированного списка P0–P3. Исторические измерения и уже закрытые
пункты остаются в `decomposition-issues-2026-10-05.md`.

| ID | Область | Наблюдение | Влияние | Зависимости | Статус |
|---|---|---|---|---|---|
| N01 | Memory evidence lifecycle | In-place semantic overwrite меняет содержимое canonical memory, но сохраняет `task_memory_links` с relation `produced`. Текущая проверка доверия использует evidence-поля самой memory, однако смысл ссылки как historical или current-content lineage не определён. | Возможна вводящая в заблуждение Task lineage в читателях, которые используют links независимо от evidence-полей. | Сначала определить контракт: историческая связь с row identity либо доказательство текущего содержимого; затем либо сохранить ссылку явно как historical, либо удалить/версионировать её в той же transaction. | Source-confirmed contract gap; реализацию не начинать без выбора семантики. |
| N02 | Memory active-state | `list_memories`, `recall_memory`, pinned `wake_up` и REST list исключают `superseded_by`, но не исключают memory с истёкшим `valid_until` и пустым successor. Singular REST read исправлен отдельно и проверяет оба признака. | Validity-only retired row может оставаться видимой через другие read surfaces. | Согласовать единый predicate active memory и применить его к SQLite/PostgreSQL, vector hydration и digest readers. | Source-confirmed follow-up; требует отдельного cross-surface regression. |
| N03 | API-key identity availability | `verifyAPIKey` возвращает пустую identity и для неизвестного/отозванного ключа, и для SQL/context failure. HTTP и MCP поэтому не отличают отказ в доступе от недоступности identity store. | Временная ошибка БД выглядит как недействительный ключ; клиент получает неверный сигнал для повторной аутентификации, а диагностика теряется. | Ввести типизированный lookup без изменения 401/404 concealment для denied; инфраструктурную ошибку отображать в 503 и проверить отсутствие verified locals/dispatch на обеих SQL-базах. | Source-confirmed отдельный follow-up; browser-session I249 исправляется независимо. |
| N04 | gRPC v2 error taxonomy | `ErrorDetail.code` объявлен как числовая категория, но proto не задаёт enum или соответствие canonical gRPC codes; сервер исторически возвращает константу `1`. | Клиенты получают текст и точный per-item identity, но не могут надёжно ветвиться по категории ошибки без разбора строки. | Сначала закрепить публичную taxonomy и совместимость значения `1`, затем заменить константу централизованным mapping и добавить contract tests. | Source-confirmed contract gap; I11 закрывает потерю ошибок и transport status независимо. |
| N05 | PostgreSQL test isolation | Тестовый helper задавал `search_path` одной session-командой. После отмены запроса pgx заменял соединение, и новая session читала public schema, создавая ложный признак утечки memory. | Deadline/cancellation тесты могли падать из-за чужих строк public schema и скрывать реальный результат rollback. | `search_path` перенесён в pgx RuntimeParams, поэтому применяется к каждому новому соединению; точный тест проходит 10 повторов на PostgreSQL и SQLite. | Исправлено 2026-10-08. |
| N06 | Project-context interactions | Aggregate принимал interaction, если хотя бы один source относился к выбранной collection, а остальные были доступны caller. Текст mixed-project interaction мог попасть в контекст соседнего доступного проекта. | Нарушалась exact project isolation при одновременном доступе пользователя к обоим проектам. | Теперь каждый source обязан иметь выбранную collection и проходить live authorization; обе-SQL regression покрывает доступный `main+sibling` interaction. | Исправлено 2026-10-08 по independent review. |
| N07 | Async consolidation accounting | Parser возвращал все нули, если error result содержал `llm_calls=N`, но не содержал progress counters. | Failed async job занижал фактическое число вызовов LLM, несмотря на правильный результат engine. | `llm_calls` разбирается независимо от optional progress counters; добавлен error-only regression. | Исправлено 2026-10-08 по independent review. |
