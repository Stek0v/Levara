# Новые проблемы после roadmap T01–T32

Этот файл содержит только дефекты и неясные контракты, найденные во время
закрытия ранжированного списка P0–P3. Исторические измерения и уже закрытые
пункты остаются в `decomposition-issues-2026-10-05.md`.

| ID | Область | Наблюдение | Влияние | Зависимости | Статус |
|---|---|---|---|---|---|
| N01 | Memory evidence lifecycle | In-place semantic overwrite менял содержимое canonical memory, но сохранял `task_memory_links(relation='produced')`. | Task lineage могла описывать уже заменённое содержимое. | Зависит от N02: сначала единое понятие active/current content. | Исправлено 2026-10-08: `produced` означает текущий fingerprint `value/type/room/hall`; native triggers обеих SQL удаляют ссылку при semantic update, exact/metadata update и rollback проверены. |
| N02 | Memory active-state | Current-read surfaces расходились по `superseded_by` и `valid_until`. | Validity-only retired row оставалась видимой и могла сохранять stale vector. | Базовый контракт для N01, N08 и N10. | Исправлено 2026-10-08: единый predicate `superseded_by='' AND valid_until IS NULL` применён к публичным reads, Task/commit, consolidation, vector migration/reconcile и diagnostics; history явно маркирует validity-only row как superseded. |
| N03 | API-key identity availability | Denied credential и SQL/context failure сводились к пустой identity. | Клиент получал 401/404 вместо retryable 503, диагностика терялась. | Независимая P0 auth-граница; выполнена первой. | Исправлено 2026-10-08: typed lookup различает denial и unavailable, dispatch/session mutation не происходят на failure; SQLite/PostgreSQL race regression пройден. |
| N04 | gRPC v2 error taxonomy | `ErrorDetail.code` был без enum и всегда равен `1`. | Клиенты разбирали текст вместо стабильной категории. | После N03, чтобы transport identity errors остались gRPC status, а response envelopes классифицировали item/application errors. | Исправлено 2026-10-08: enum сохраняет wire value `1` как `LEGACY`, добавлены INVALID_ARGUMENT/NOT_FOUND/FAILED_PRECONDITION/UNAVAILABLE/INTERNAL; реальные Insert/alias/Delete/batch пути сохраняют typed cause до v2 mapping; stubs сгенерированы. |
| N05 | PostgreSQL test isolation | Тестовый helper задавал `search_path` одной session-командой. После отмены запроса pgx заменял соединение, и новая session читала public schema, создавая ложный признак утечки memory. | Deadline/cancellation тесты могли падать из-за чужих строк public schema и скрывать реальный результат rollback. | `search_path` перенесён в pgx RuntimeParams, поэтому применяется к каждому новому соединению; точный тест проходит 10 повторов на PostgreSQL и SQLite. | Исправлено 2026-10-08. |
| N06 | Project-context interactions | Aggregate принимал interaction, если хотя бы один source относился к выбранной collection, а остальные были доступны caller. Текст mixed-project interaction мог попасть в контекст соседнего доступного проекта. | Нарушалась exact project isolation при одновременном доступе пользователя к обоим проектам. | Теперь каждый source обязан иметь выбранную collection и проходить live authorization; обе-SQL regression покрывает доступный `main+sibling` interaction. | Исправлено 2026-10-08 по independent review. |
| N07 | Async consolidation accounting | Parser возвращал все нули, если error result содержал `llm_calls=N`, но не содержал progress counters. | Failed async job занижал фактическое число вызовов LLM, несмотря на правильный результат engine. | `llm_calls` разбирается независимо от optional progress counters; добавлен error-only regression. | Исправлено 2026-10-08 по independent review. |
| N08 | MCP resource memory isolation | `resources/read` читал memories через `context.Background()` без verified owner и active filters. | Authenticated caller мог получить foreign или retired memory через отдельный MCP surface. | Зависит от N02 active predicate и N03 verified identity boundary. | Исправлено 2026-10-08: request context, verified identity, own/shared scope и active predicate; обе-SQL regression. |
| N09 | gRPC batch metadata validation | v1 `BatchInsert` игнорировал ошибку JSON decode и сохранял item с nil metadata. | Malformed client data принималась как успешная запись; v2 не мог выдать точный typed failure. | Зависит от N04 taxonomy. | Исправлено 2026-10-08: malformed item не достигает storage, сохраняет исходные index/id и возвращает `INVALID_ARGUMENT`; valid siblings продолжают batch. |
| N10 | Validity-only key reuse | Retired row с `valid_until` и исходным unique key ловил последующий upsert; новый value записывался в невидимую retired identity. | Save сообщал успех, но current recall не видел запись; historical content перезаписывался. | Зависит от N02 active predicate и согласуется с N01 lineage. | Исправлено 2026-10-08: общий writer-путь атомарно архивирует retired key и создаёт новую active identity; покрыты save_memory, diary_write, chat_distill, Task promotion, Memory Commit и REST на SQLite/PostgreSQL. |
