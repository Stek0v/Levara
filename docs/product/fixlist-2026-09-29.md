## P0

### F1. task-load-gate S3: outbox не дренируется без embed-провайдера (CI red) — ✅ ИСПРАВЛЕНО 2026-09-29

- **Симптом:** джоб «task runtime load gate (S2/S3)» падает на ветке: S3
  `drained=false`, 435 джобов вечно `pending`, exit 1. S2 — pass. На main
  (8f49a0e) тот же гейт — PASS, exit 0 (все джобы терминальны).
- **Факты:** 435 pending имеют одинаковый `next_run_at` — одна волна Defer.
  306669f ввёл в `pkg/memoryindex/outbox.go` cooldown в `Claim`, новый `Defer`
  (вызывается из `internal/http/memory_index_worker.go:117` при
  `embed.BreakerOpenError`) паркует джоб с refund попытки. Без провайдера джоб
  никогда не терминален. Это незакрытая половина приоритета №2 из
  `docs/fact-quality-repairs-2026-09-29.md` («контролировать завершение
  индексации»). Упало бы и в GitHub CI — не флейк (воспроизведено дважды).
- **Фикс (выполнен, две части):**
  1. `Defer` больше не рефандит попытку; при `attempts >= maxAttempts` джоб
     уходит в `dead_letter` (с сохранением исходной ошибки, `memory_index_retry`
     возвращает после восстановления). Воркер передаёт общий
     `memoryIndexMaxAttempts=5`. Тесты на SQLite и Postgres переписаны под
     новую семантику (парк без refund, кап→dead_letter, fencing, last_error).
  2. Гейт-скрипт стал честным: S3 требует «exactly once», но её серверы не
     могли эмбеддить в принципе (primary без endpoint; secondary просил
     potion-code-16M, который бэкенд не отдаёт → dim mismatch) — в CI джоб
     проходил только вакуумно через гонку дрена. Обоим серверам теперь даётся
     детерминированный embed-stub (stdlib, CI-safe,
     `--embed-endpoint/--embed-model` в multi_user.py).
- **Результат:** `TASK_LOAD_GATE: PASS`, exit 0; S3 = 1000/1000 completed,
  dead_letter=0, duplicate_completions=0, drained=true; S2 pass. -race,
  lint (0 issues), полный internal/http — зелёные.
