# Проверка качества и достоверности фактов Levara

Цель: возвращать нужные, актуальные, доступные пользователю факты вместе с
проверяемым основанием. Совпадение по смыслу, метка `verified`, успешный HTTP
и наличие цитаты по отдельности этого не доказывают.

## Что считать доказательством

Проверяем цепочку: источник → запись/фрагмент → индекс → поиск → контекст →
ответ. Для каждого теста заранее фиксируем ожидаемые атомарные факты, IDs,
полный исходный текст, область доступа, временную версию и допустимые ответы.
Синтетический эталон устанавливает истину только внутри тестового мира.
Для реальных проектных фактов нужны первичные источники и независимая проверка
владельцем предметной области; совпадение с ошибочным источником не делает
утверждение истинным.

Используем три независимых результата:

1. **Поиск:** нужные источники найдены, все необходимые факты доступны.
2. **Доверие:** происхождение и актуальность проверены; нет чужих данных и
   необоснованного повышения статуса подтверждения.
3. **Ответ:** каждое утверждение поддержано указанным источником; при нехватке
   сведений ответ признаёт неопределённость, при конфликте показывает конфликт.

## Матрица методов

| Метод / риск | Проверка и метрика | Исполнение этого этапа |
|---|---|---|
| Контракты MCP/REST | Типы, ошибки, совместимость, реальный dispatch | Существующие Go-тесты |
| Сохранность атомарного факта | Полный текст, числа, единицы, имена, отрицания без изменений | Общий синтетический корпус |
| Точный и семантический поиск | Recall@1/3/5/10, precision@k, MRR, все gold IDs | Реальная локальная embedding-модель |
| Русский/английский, перефразы | Отдельные срезы; запрос не копирует текст источника | Общий корпус |
| Похожие ложные кандидаты | Соседние числа, другая сущность, противоположное отрицание | Общий корпус |
| Несколько источников | Полнота ВСЕХ необходимых фактов, а не попадание одного | Общий корпус |
| Фильтры room/hall | Потери из-за фильтра после top-k; >10 отвлекающих записей | Общий корпус и действующие регрессии |
| Коллекции и владельцы | Ноль чужих IDs/значений, одинаковые ключи у разных владельцев | Изолированный сервер с JWT + Go-тесты |
| Актуальность | Supersede/delete/upsert, старые версии исключены; история явно помечена | Публичные операции и Go-тесты |
| Проверка evidence | Поддельные/чужие/устаревшие receipts, ошибочный exit code, подмена digest | Prepared commit регрессии + диагностические пробы |
| Статус доверия | Caller-asserted label отделён от server-validated linkage | Пробы save/supersede/Task promotion |
| Конфликт и неизвестный ответ | Оба конфликтующих источника; отсутствие утверждения без основания | Retrieval-диагностика + ограниченный локальный answerer |
| Цитаты и атомарные утверждения | Источник существует, доступен, содержит именно заявленный факт | Детерминированный oracle; не LLM-судья |
| Prompt injection в данных | Инструкция из источника не становится ответом/действием | Ограниченный answerer, без исполнения инструментов |
| Устойчивость индекса | Сбой embedding, повтор outbox, гонки удаления/публикации | Существующие Go-тесты и race detector |
| Диалекты и режимы | SQLite/PostgreSQL; SQL-only против semantic; ошибки не маскируются | Изолированные БД; отдельные результаты |
| Модели и rerank | Одинаковые кандидаты, запросы, labels; paired delta качества/задержки | Только доступные модели; расширенная модельная матрица отдельно |
| Chunking/OCR/таблицы | Сохранность отрицаний, чисел, таблиц и связи утверждение–страница | Следующий корпус с размеченными реальными документами |
| Масштаб и нагрузка | Качество при росте distractors; p50/p95/p99, таймауты и ошибки | Небольшой distractor stress сейчас; нагрузочный soak отдельно |
| Рестарт/backup/sync | После восстановления те же активные факты, provenance и ACL | Отдельная destructive/fault кампания в тестовой среде |
| Метаморфные проверки | Перестановка вставки, парафраз, добавление шума не меняют истину | Негативные контроли scorer; повторяемый корпус |
| Независимый holdout | Разделение по фактам/проектам, а не только формулировкам запросов | Существующий 59-query holdout; новый корпус пока developer-authored |
| Экспертная/production оценка | Двойная разметка, разбор расхождений, feedback и drift | Требует реальных подтверждённых источников и отдельного rollout |

Полный декартов набор моделей, языков, объёмов и режимов бесконечен практически.
Сначала закрываем классы ошибок; затем расширяем матрицу по найденным рискам.
Нельзя заменять эти независимые измерения одним смешанным баллом CRUD+скорость+качество.

## План первого запуска

- Зафиксировать commit, fixture SHA256, модель/dimension, режимы и реальные
  настройки сервера. До тестов проверить зависимости, SQL, embedding и auth.
- Поднять отдельный Levara с пустой SQLite и отдельным vector directory;
  отдельный PostgreSQL использовать для диалектных регрессий. Наследование
  production DSN, workspace/watchers и удалённых LLM endpoints исключить.
- Поместить десятки фактов и трудных distractors в ОДНУ основную коллекцию,
  дождаться индексации, затем выполнить заранее зафиксированные запросы.
  Соседняя коллекция и второй пользователь служат проверке изоляции.
- Использовать не менее 30 запросов: перефразы, числа/единицы, отрицания,
  версии, несколько фактов, фильтры, неизвестные и конфликтующие сведения.
- Сохранять каждый запрос, сырые результаты и длительность; проверять не
  только ID, но точный текст и scope. Известный релевантный ID с испорченным
  значением не засчитывать. Дубликаты не увеличивают полноту.
- Цель маленького синтетического набора: каждый требуемый факт в top5;
  ноль утечек, устаревших активных записей и искажений текста. Это строгая
  диагностическая цель, не статистическое обещание качества на production.
- Для вопросов без ответа отдельно считать nonempty retrieval. Возвращённый
  кандидат сам по себе ещё не ложное утверждение: отказ от ответа оценивается
  в answerer. Конфликтующие факты нельзя автоматически объявлять истинными.
- Проверить scorer отрицательными контролями: неверный ID, верный ID с ложным
  текстом, пропущенная половина multi-hop, чужая коллекция, дубликаты, пустой
  ответ, несуществующая цитата. Не использовать модель для оценки самой себя.
- Пропуски, unavailable и ошибки показывать отдельно и включать в ожидаемое
  число проверок; не выдавать их за успех. Не исправлять oracle после просмотра
  плохих результатов. Найденные продуктовые дефекты сохранять как результаты.

## Методические основания и пределы

[LongMemEval](https://arxiv.org/abs/2410.10813) разделяет извлечение,
межсессионное/временное рассуждение, обновления и abstention; это полезная
таксономия для памяти, но здесь не заявляется запуск его полного benchmark.
[FActScore](https://aclanthology.org/2023.emnlp-main.741/) оценивает поддержку
атомарных утверждений источником; заимствуем принцип, а не его численные результаты.
[ALCE](https://aclanthology.org/2023.emnlp-main.398/) разделяет корректность
ответа и качество цитирования. [BEIR](https://arxiv.org/abs/2104.08663)
обосновывает проверку retrieval на разных доменах и сравнение с lexical baseline.

Наши детерминированные проверки не заменяют оценку мировых фактов, качества
произвольного длинного ответа, production-нагрузки или экспертную разметку.
Даже валидный receipt удостоверяет структуру подтверждения, а не автоматически
смысловую связь его содержимого с каждым сохранённым утверждением.
