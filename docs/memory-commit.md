# Подготовленное сохранение памяти

`memory_commit_preview` и `memory_commit_apply` доступны при
`LEVARA_MEMORY_COMMIT=true` в профилях, включающих эти инструменты. Preview
сохраняет временный SQL-план на 30 минут; строки памяти меняет только apply.
Проверяйте активный список MCP-инструментов: флаг не расширяет профиль клиента.

## Preview и выбор изменений

Передайте `collection`, новый `idempotency_key` и от 1 до 20 `candidates`.
Каждый кандидат содержит `candidate_id`, `key`, `value`, `room`, `hall`.
Для явной замены добавьте `supersedes_memory_id`. Значение ограничено 64 КиБ;
список источников — 64 receipt ID. Collection и ключ идемпотентности ограничены
256 байтами. Секреты, распознанные существующей проверкой значений, отклоняются;
это не полноценный сканер всех возможных секретов.

Preview возвращает `commit_id`, `plan_digest`, `expires_at`, сводку и действия
`add`, `supersede`, `skip`, `conflict`, `reject`. Повтор с тем же ключом и тем же
запросом возвращает сохранённый план. Другой запрос с тем же ключом отклоняется.
Истёкший план требует нового ключа; завершённый план повторным preview не
перезаписывается.

Для apply передайте точные `commit_id` и `plan_digest`. Параметр
`accepted_candidate_ids` управляет выбором:

- Параметр отсутствует: применяются допустимые `add`, `supersede`, `skip`.
- Явный пустой массив `[]`: ни один кандидат не выбирается; план завершается без
  записи памяти.
- Непустой массив: выбираются только перечисленные допустимые кандидаты.
  Неизвестные ID и неверный тип параметра отклоняются.

Повторный apply уже завершённого плана возвращает сохранённый результат и не
расширяет первоначальный выбор. При изменении целевой памяти, отзыве полномочий
или недействительных доказательствах вся транзакция откатывается, включая
подготовленные задания индексации.

## Что означает проверка доказательств

Без источников сервер сохраняет `verification_status="unverified"`. Входное
поле `verification_status` оставлено для совместимости; оно не повышает статус.
Чтобы проверить связь с Task Runtime, передайте одновременно `source_task_id`
и непустой `source_receipt_ids`.

Сервер проверяет существование task в точной collection и с точным владельцем
текущего запроса. Каждый receipt должен принадлежать этой task и этому владельцу,
иметь `status="pass"` и непустую ревизию, совпадающую с текущей ревизией task.
Для command receipt обязателен явный `exit_code=0`. Для artifact receipt нужны
URI и полный SHA-256; доступный серверный `ArtifactVerifier` должен проверить
текущие байты. При указанном artifact digest такая проверка требуется также для
другого типа receipt. Дублирующиеся receipt ID отклоняются.

Успешная проверка даёт `receipt-validated` в preview и в новой строке памяти.
Эта метка означает проверенные связи, форму и актуальность указанных receipt
на момент операции. Она **не подтверждает истинность текста памяти** и не
означает, что сервер заново выполнил команду из caller-supplied receipt.
Preview — сохранённое предложение; его результаты могут устареть. Apply
повторяет проверку источников внутри транзакции перед публикацией.

## Полномочия и ограничения

Оба инструмента требуют действующих полномочий записи. Сервер получает личность
из аутентифицированного контекста, проверяет активность пользователя, актуальность
credential и разрешения API-ключа. Отсутствие credential не включает no-auth:
для локального режима нужен явно настроенный `TrustedLocal`.

Обычный пользователь может изменять собственную память. Заменять общий факт
с `owner_id=''` может подтверждённый текущей SQL-проверкой администратор или
явно доверенный локальный вызов; общий владелец при замене сохраняется.
Доступ к общим строкам памяти не даёт доступа к чужим task или receipt.

Операция наследует срок родительского запроса и ограничена 30 секундами.
Авторизация и сравнение памяти защищены SQL-транзакцией; PostgreSQL использует
блокировки таблиц, SQLite — транзакцию записи. Это может задерживать параллельные
изменения во время проверки больших артефактов. ArtifactVerifier должен соблюдать
контекст, авторизовать фактический доступ и читать через переданную сервером
политику этой же транзакции; отдельное соединение опасно для пула из одного
соединения. Эти проверки не изменяют семантику самостоятельного `task_complete`
или других инструментов сохранения памяти.
