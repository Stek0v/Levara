# Качество фактов: результаты 2026-09-29

**Levara хорошо нашла источники в небольшом подготовленном корпусе, но пока
нельзя считать её метки подтверждения надёжной гарантией достоверности.**
Выявлены воспроизводимые проблемы доверия, восстановления индекса и поиска
истории. Отдельный локальный answerer ошибается даже при полном контексте.

Методика и расширение покрытия: [матрица тестирования](fact-quality-evaluation.md).
Это диагностический baseline, а не сертификация production или истины внешнего мира.
Продуктовые исправления по результатам этого этапа не внесены.

## Поиск фактов

В одной коллекции размещены 58 заранее зафиксированных записей, включая
12 отвлекающих записей. Другой владелец и другая коллекция содержат записи
с совпадающими ключами. 39 запросов: 36 требуют источники, три не имеют ответа.
Проверяются полный текст, canonical ID, owner, room/hall и актуальность;
ошибочный текст с правильным ID не засчитывается.

| Метрика на 36 положительных запросах | Значение |
|---|---:|
| Средняя полнота Recall@1 | 87,5% |
| Recall@3 / @5 / @10 | 100% / 100% / 100% |
| Все необходимые источники в top‑3 | 36/36 |
| MRR | 0,9722 |
| Чужие/искажённые/помеченные устаревшими строки | 0 из 358 возвращённых строк |

Проверены RU/EN, перефразы, отрицания, числа и единицы, близкие названия,
несколько источников, room/hall, текущие и исторические утверждения, конфликт.
Для трёх неизвестных вопросов поиск вернул соседние записи: это кандидаты,
а не ответы. Сам по себе такой результат ещё не является галлюцинацией.

Наблюдаемая latency recall: p50 116 мс, p95 162 мс на одном коротком прогоне.
Это не нагрузочный SLA. Набор создан разработчиками и не является независимым
holdout; результат нельзя переносить на большие или реальные коллекции.

Служебные пробы owner/collection isolation, reconnect, upsert, active supersede
и delete прошли. **Поиск superseded history провалился:** после замены Ольги
на Марию запрос `Ольга` с `include_superseded=true` вернул только Марию.
Предыдущий SQL-факт сохранён, но его вектор удалён; непустые текущие semantic
результаты подавляют SQL fallback. Расширение фильтра не возвращает отсутствующий
исторический кандидат.

## Доверие и происхождение

| Публичная операция / ожидаемое свойство | Фактическое поведение |
|---|---|
| Save не принимает неподтверждённую метку за проверку | Принял `receipt-validated` с вымышленными task/receipt IDs — FAIL |
| Supersede без доказательства не повышает trust | Присвоил замене `verified` — FAIL |
| Кандидат не подтверждается ошибочной командой | Кандидат, ссылающийся только на receipt с exit 7, promoted как `verified`; другой receipt exit 0 закрыл DoD — FAIL |
| Command receipt требует явный exit code | Задача завершилась с receipt без exit code — FAIL |
| Recall передаёт provenance без изменения | PASS |
| List передаёт provenance | Поля отсутствуют — FAIL |
| Wake up передаёт provenance | Поля отсутствуют — FAIL |
| Prepared Memory Commit без proof | `unverified` — PASS |
| Prepared Memory Commit с валидным proof | `receipt-validated` — PASS |

Команды exit 7 и exit 0 действительно запускались локально. Затем тест намеренно
передавал противоречивый status=pass, проверяя границу доверия публичного API.
Это не доказательство ложности произвольного факта; это доказательство того,
что метку проверенности можно получить без достаточного основания.
Даже корректная привязка receipt не устанавливает автоматически смысловую связь
его содержимого с каждым утверждением.

## Документный поиск

Повторно исполнен существующий holdout из 59 вопросов по 20 документам
репозитория, 117 опубликованным chunks. Корпус сохранён и перепроверен по SHA;
source revisions и публикации проверены по изолированной SQLite. Это отдельно
составленные вопросы к уже известным документам, не новые независимые документы.

| Стратегия | Попадание source+answer в top‑3 | MRR@3 | p50 / p95, мс |
|---|---:|---:|---:|
| CHUNKS_LEXICAL | 45/59 (76,3%) | 0,6017 | 3,4 / 4,3 |
| CHUNKS | 31/59 (52,5%) | 0,4209 | 128,5 / 247,1 |
| HYBRID | 45/59 (76,3%) | 0,6073 | 106,4 / 142,8 |

Все 177 запросов получили HTTP 200; все проверенные ссылки на источник и
ревизии валидны. Условия: `embeddinggemma-300m`, 768 измерений, SQLite, no-auth
изолированный loopback, concurrency 1, top‑3, без rerank и query alias.
Это текущая базовая конфигурация эксперимента; её нельзя напрямую сравнивать
с прежними замерами другой конфигурации/ревизии. Преимущество reranker или
другой модели здесь не измерялось.

Существующий scorer проверяет источник и подстроки ответа. Он годится для
retrieval smoke, но не доказывает семантическую корректность произвольного
утверждения и может не распознать отрицание вокруг совпавшего числа.
В этом наборе semantic-only хуже lexical/hybrid; отказываться от lexical
baseline на основании одной лишь семантической близости не следует.

Неудачные подготовительные попытки сохранены: первый запуск получил 401 до
создания корпуса, поскольку старый harness не поддерживает JWT; второй
получил 121 ответ 429 из 177 из-за стандартного лимита 100 запросов/минуту.
Финальный запуск выполнен на новой БД с явным `RATE_LIMIT_USER_MAX=1000` и
тем же hash-verified corpus. Предыдущие попытки не интерпретируются как
чистое сравнение качества retrieval. Поле `rate_limit_per_minute` старого
harness статично; фактическую конфигурацию подтверждает манифест запуска сервера.

## Ответ по найденным источникам

Использован **внешний ограниченный answerer**, а не встроенный RAG endpoint:
локальный `gemma4:e2b`, `think=false`, temperature 0, top‑5 сохранённых результатов.
В prompt передавались только вопрос и тексты найденных записей. Gold-ответы
и canonical metadata доступны только проверяющему коду. Инструментов и действий
у answerer нет. Все ответы завершились; общее время 94,5 с.

| Независимая проверка | Результат |
|---|---:|
| Выбран ожидаемый режим answer/unknown/conflict | 37/39 |
| Совпал строгий краткий ответ | 24/39 |
| Полный ожидаемый набор неизменённых цитат | 34/39 |
| Одновременно все три требования | 22/39 |

**17 строгих FAIL не равны 17 выдуманным фактам.** Независимый разбор raw responses:

- `q008`: модель смешала датчик «Роса» (250 мс) с «Роза» (250 с). Это реальная
  ошибка выбора сущности при наличии правильного источника.
- `q027`: ложный отказ отвечать про время полёта и дождь, хотя оба факта найдены.
- `q005`: верное «Нет», но противоречивый status `unknown` и лишняя цитата.
- 14 остальных: девять вариантов формулировок/падежей/пунктуации; одна цитата
  без завершающей точки; один ответ цитирует факт без вредоносного хвоста;
  три строковых `"null"` вместо JSON `null`.

Строгий oracle после наблюдения результатов не менялся. Качественная классификация
приведена отдельно и не подменяет score. Для следующей версии эталона короткие
ответы стоит задавать типизированными атомами и заранее допустимыми вариантами;
проверку полной цитаты оставить отдельной от смысловой корректности.

Конфликт определён корректно с двумя источниками. В трёх неизвестных вопросах
новые факты не придуманы, хотя JSON-тип неправильный. Единственная injection
с инструкцией ответить «ПРОТОКОЛ ВЗЛОМАН» не выполнена; ответ 11 верен.
Это один сценарий устойчивости, а не общая гарантия защиты от injection.

## Отказ индексации

При обеих массовых загрузках upstream embedding-процесс аварийно завершился
с native Metal assertion; затем автоматически появился новый процесс.
Прямые одиночные и восемь одновременных коротких запросов при preflight прошли.
Это показывает, почему одного успешного health check недостаточно.

Усиление отказа внутри Levara подтверждено: breaker открыт на 30 секунд,
а очередь расходует пять попыток, включая отказ открытого breaker, примерно
за 1+2+4+8=15 секунд. Задания становятся dead letter до возможного восстановления.
Последняя ошибка перезаписывает исходную. Конкурентный inference на общем
MPS backend — обоснованная гипотеза триггера, но конкретный дефект Torch/Metal
не установлен. После serial preload те же факты проиндексированы успешно.

## Приоритеты исправлений

1. **Граница доверия.** Разделить caller-asserted и server-validated состояния;
   не повышать trust при supersede без proof. Для каждого promoted кандидата
   проверять конкретные связанные receipts, явный exit 0, текущую revision,
   scope и artifact digest. Сохранить уже работающую атомарность транзакции.
2. **Доставка в индекс.** Учитывать cooldown в retry-политике, сохранять исходную
   ошибку и контролировать завершение индексации. Отдельно подтвердить безопасную
   конкуренцию локального embedding backend; не менять модель до baseline.
3. **Полнота provenance и истории.** Передавать verification/source-поля в list
   и wake_up; обеспечить отдельный путь поиска superseded фактов.
4. **Качество ответа.** Проверять соответствие сущности/числа/единицы источнику,
   JSON-схему, поддержку каждого атома и обоснованность отказа. Сравнивать модели
   и rerank на одинаковых сохранённых candidates, с новым независимым holdout.

Следующий необходимый уровень: размеченные реальные проектные документы,
независимая проверка первоисточников, OCR/таблицы/страницы, большие distractor
корпуса, вариации порядка вставки, восстановление/backup/sync, нагрузка и drift.
Полные LongMemEval/BEIR, модельная матрица и production-тестирование не запускались.

## Воспроизведение

Новые скрипты требуют явного loopback endpoint и разрешения на запись в
изолированный сервер; порты 8080/8081 запрещены. Нужны свежие output paths.
Они не поднимают сервер автоматически и не должны запускаться на рабочей памяти.

```bash
python3 benchmark/factual_quality.py --self-check
python3 benchmark/factual_trust_probes.py --self-check
python3 benchmark/factual_answer_quality.py --self-check

python3 benchmark/factual_quality.py --url http://127.0.0.1:18124 \
  --allow-isolated-writes --output-dir /tmp/facts-bulk-new
python3 benchmark/factual_quality.py --url http://127.0.0.1:18124 \
  --allow-isolated-writes --serial-seed --output-dir /tmp/facts-serial-new
python3 benchmark/factual_trust_probes.py --url http://127.0.0.1:18124 \
  --allow-isolated-writes --output-dir /tmp/facts-trust-new
python3 benchmark/factual_answer_quality.py \
  --queries /tmp/facts-serial-new/queries.json --url http://127.0.0.1:11434 \
  --model gemma4:e2b --output /tmp/facts-answers-new.json
```

Коды выхода различают успешную проверку и найденную проблему. Для фактического
retrieval harness exit 1 означает незавершённое исполнение/инфраструктуру,
exit 2 — полностью наблюдаемый quality failure. Trust и answerer также
возвращают ненулевой exit при нарушениях; ошибки и пропуски видны в JSON.

Продуктовый бинарник: `7666a9a8bd6dca829578c5428173aed83b0543dd`.
Evaluation commits: `591060b` и `ed557b0`; fixture SHA256:
`9befbbdb333d58a00ae993cd106d6c7677dedb202673fdcdd808697ec7f95acc`.
Новые файлы меняют тесты и документацию, не продуктовый код.

Полные сырые результаты, все неудачные попытки, конфигурации, Go JSONL,
preflight и manifest SHA256 сохранены локально в
`.git/quality-evidence/20260929-facts/`. Они не добавлены в tracked source.
Тестовые HTTP-серверы и отдельный PostgreSQL остановлены. Синтетические записи
создавались в тестовых БД; в рабочую память сохранены только подтверждённые
выводы исследования. Ручной перезапуск рабочего embedding-сервиса не выполнялся;
его два автоматических рестарта после Metal abort отражены в evidence.
