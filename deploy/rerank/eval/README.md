# Rerank evaluation fixtures

This directory provides corpus helpers for rerank chaos, soak and performance
experiments. It does not establish current end-to-end ingestion compatibility
or a measured quality improvement. See [testing](../../../docs/testing.md).

## Files and local inspection

- `mteb_scidocs_reranking.jsonl` — untracked corpus, with one JSON record per
  line: `{"query":"...","positive":["doc"],"negative":["doc"]}`.
- `corpus_fixture.py` — `load_scidocs`, `flatten_docs`, `make_queries` and
  `seed_collection` helpers. Loading is stdlib-only; ingestion imports `requests`.
- `dump_fixture.py` — local corpus statistics:

  ```bash
  python3 deploy/rerank/eval/dump_fixture.py
  ```

Override the corpus path with `MTEB_SCIDOCS_PATH`. IDs generated by the helper
are `sci-<sha1(text)[:8]>`. This truncation is convenient for the fixture but
is not a collision-free identifier scheme. Save the corpus digest with results.

## Preparing a reproducible corpus

The helper expects the structure of the HuggingFace `mteb/scidocs-reranking`
dataset. The old regeneration example selected the mutable upstream default;
it did not pin a dataset revision. To compare runs, acquire a fixed revision
and record its revision, split, row count and the SHA-256 of the resulting JSONL.
Keep the same file for baseline and candidate runs. Use a separate Python
environment if importing the optional `datasets` library to prepare the file.

The helper's first-occurrence deduplication may assign a document the first
label it encounters. Relevance must be judged per query from `make_queries`,
not from the document's single `label` field.

## Ingestion helper: current limitation

`seed_collection` posts document text to `/api/v1/add`, then sends inline
`texts` to `/api/v1/cognify` and polls its run status. The server also exposes
a direct vector insert route; the old claim that no insert route exists was
incorrect. Choose the document path when testing extraction/indexing and the
vector path only when that is the experiment's intended scope.

The helper currently recognizes lowercase terminal statuses such as
`completed` and `failed`, while the server returns `COMPLETED` / `FAILED`.
It can wait until its deadline and return a status without proving success.
It also returns early when no run ID is present. Treat current E2E seeding as
**unverified** until these conditions are checked and the expected documents
are actually retrieved. The generated `sci-*` IDs are not explicitly supplied
to `/add`; do not assume they equal the IDs returned by search.

If adapting a run, supply an explicit disposable server origin, test token,
unique dataset/collection and independent database. Inspect responses and
record accepted document count, run completion, retrieval IDs and errors
before measuring rerank. Never use a live collection as the fixture target.

## Reading results

Compare baseline and rerank using the same corpus/query digests, top-K and
relevance mapping. Report quality metrics separately from latency, failed
requests and skipped queries. An importable fixture or a successful chaos test
does not demonstrate improved retrieval quality.
